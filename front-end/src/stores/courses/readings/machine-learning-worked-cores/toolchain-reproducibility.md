# Keep the source, inputs and result together

A saved library project contains `main.py`, `exercise.py`, `README.md`, `SOURCES.md`, `requirements.txt` and its local CSV when the example uses one. Preserve the original input file and source revision while changing the exercise.

Record the command, Python version, installed library versions, seed, split rule and output filenames. The generated JSON report carries model evidence; figures make the same result inspectable. Keep training and held-out group counts, fitted preprocessing and the baseline with the metric.

For example, the customer-neighbor project uses 200 rows, a fixed 150/50 split and labels generated by a training-only clustering rule. Repeating that source and environment preserves the comparison being made. Its score measures imitation of the fitted rule on those observations.

Rerun from the beginning after changing code. Compare input counts, split identities and numerical results using the project's stated tolerances. Record the environment when numerical libraries or hardware produce a small floating-point difference. A repeatable plot supports the recorded computation; interpretation still depends on the supplied observations, features and question.
