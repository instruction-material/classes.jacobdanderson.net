# Review a model and its explanation

Use these criteria when checking a completed project:

| Criterion | Evidence |
| --- | --- |
| Reproduce the result | Source revision, local input, environment and run command regenerate the report. |
| Preserve the fit boundary | Learned preprocessing, model selection and final testing use the declared partitions. |
| Compare on equal terms | Baseline and model use the same evaluated rows, label order and stated metrics. |
| Explain the result | One retained error or trace, one data limitation and a justified next experiment support the conclusion. |

## Worked review

The supplied customer-neighbor reference reports 0.96 accuracy on 50 held-out rows, compared with a training-only majority baseline of 0.42. Its split, fitted clustering rule and prediction table show what was measured: imitation of labels generated by that training rule.

A complete explanation names this generated-label target, keeps the 150 training rows separate and inspects an actual reported error. It also retains macro F1 and the ordered confusion matrix. A high score alone leaves those review criteria unresolved.

For a starter, the fitting function must be completed before a full report can be evaluated. An unexpected result can still supply useful evidence when the input, calculation and limitation are accurately explained. Preserve that evidence while diagnosing its cause.
